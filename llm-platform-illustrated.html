AI 平台工程

第 一 讲

从各自直连,到一扇城门

AI 应用的野蛮生长史都是同一幕:各团队各申请 key(密钥散落代码库)、各自定价(月底财务对不上谁花的)、各自挑模型(升级要改 30 个仓库)、出事没有审计现场。AI 网关=把这些"平台级关切"从应用里抽走:统一认证与配额、按团队计量、模型路由与热切换、语义缓存、内容安全前置、全量留痕。形态两类:云厂商 AI Gateway(Helicone/LiteLLM 网关形态)或自建 Envoy/AISIX 插件——本质同普通 API 网关,只是多懂"token、流式、会话亲和、prompt 版本"这几个 LLM 特有趣味。第 0 册的"穿透击穿"在这里换了主语,但网关的军规一条没变:自己必须集群化、旁路能力不阻塞主路径、配置热更。

第 二 讲

级联路由:让 80% 的题死在便宜模型手里

路由的三层进阶:规则路由(按应用/任务类型硬编码档位,起步够用)→ 语义路由(给请求分类:简单问答/复杂推理,小分类器甚至 embedding 相似度即可判)→ 级联(cascade):先小模型作答+自报置信度(或一个裁判校验),不合格才升级大模型——质量贴近全大模型,成本接近全小模型。代价:两次延迟、置信度判定本身要评测(校准不好=白付两级)。第 3 册线程池、第 12 册投机解码是同一个哲学:用便宜手段吸收大头,贵手段处理长尾。

图 1100 个混合请求 · 「全旗舰」vs「级联」的三本账

任务构成:65 简单/25 中等/10 难。级联版:小模型接 63 个(2 个误判升级),旗舰只接 37 个——成本 −58%、均分只差 0.8。这 0.8 值不值 ¥,就是你给 CFO 的那道选择题。

第 三 讲

Prompt 是代码,得进注册表

散落在业务字符串里的 prompt,是 AI 系统最脆的资产:改了一个字没人知道影响哪些流量、线上效果回退了找不到那一次改动。平台化的解法把它当代码+配置管:中央 prompt registry(模板+变量+版本+归属应用)、网关按 app_id+version 拉取渲染、发布走评测闸门(下一讲)、流量可 A/B(同用户哈希锁桶,指标对比胜出全量)、出问题秒级回滚版本。配套纪律:模板里"指令段/数据段/少样本"结构化分层(与注入防御直接相关——用户数据永远落在不可信区);变量渲染做长度与字符卫生;每个版本挂效果与成本曲线,让"更好的 prompt"是统计结论不是玄学。

第 四 讲

评测进 CI:把"感觉变好了"开除出工程

改 prompt/换模型/升级依赖,没有评测集就是开盲盒。平台化的做法把 eval 做成流水线的一等公民:PR 改动命中 prompt/模型/检索配置 → 触发评测集(任务用例+判分器:规则、LLM-as-judge、人标对照三混)→ 通过率低于阈值或关键回归 → CI 红灯,禁止合并/发布;全量评测太贵就走"冒烟集 20 题必跑、完整集夜间跑"两级;评测产物(分维度得分、成本、延迟对比)回贴 PR 评审页。三个务实细节:评测集要版本化并与生产事故联动(每个线上翻车 case 沉淀成评测题——评测集的含金量=事故复盘的沉淀量);裁判模型与被测模型避嫌(同家族偏差);通过率阈值别拍脑袋,用历史波动带定。

图 3一次真实的 PR:改了检索 top-k,评测闸门亮灯

正常 PR:构建→冒烟评测 20 题通过→完整集 91.2%≥基线−0.5σ→绿;坏 PR:幻觉率 +11%、拒答场景通过率跳水——红灯拦下的不是运气差,是把「体感」关进了可重复的笼子。这一条,就是 AI 团队和"prompt 游击队"的分水岭。

第 五 讲

LLM 可观测:trace 里长出来的成本账

一次"AI 功能"的调用链=网关→路由决策→(检索→重排→)模型调用(可能多次工具往返)→护栏检查→后处理。普通 APM 看不见中间这些"非 RPC 环节"——LLM 观测要在 span 上挂语义属性(gen_ai.* 的 OTel 约定):模型名、输入输出 token 数、温度、prompt 版本、工具调用参数、护栏判定。四件套看板:① 质量代理指标(拒答率/负反馈率/裁判抽样分);② 成本(按 app×用户×模型的 token 账单实时透视);③ 延迟分解(TTFT 与生成段分开看,否则"慢"查不到是排队还是解码);④ 行为回放(采样留全量 prompt/completion,事故能原样复现——隐私合规红线:留痕要脱敏分级,不是全都存原文)。

图 4一次客服 agent 调用的 trace 瀑布 · 每根条都带着钱

最贵的不是大模型那 6K token,是工具循环里那次"检索+重排+两级模型"的全家桶。没有这张图,你只能对老板说"AI 变贵了";有了,你能说"3 号会话平均 4.2 次工具往返,建议加语义缓存+砍掉重排"。

第 六 讲

租 API 还是自建推理:算盈亏线

第 16 册说过:decode 是访存生意,自建推理(vLLM/SGLang+GPU 池)的吞吐优化能到 API 单价的 1/5~1/10,但固定成本(GPU 卡+运维+碎片化利用率)在那里蹲着。决策三问:量到盈亏线了吗(日 token 账单连续数月 > 自建 TCO 1.5 倍才值得);数据与合规逼不逼你自建(私有化交付/数据出境/行业监管,有时不是经济题是准入题);需求形状配不配(稳定吞吐好摊成本,波峰波谷 10 倍的场景云 API 弹性更省)。折中谱系:主力走 API+敏感链路自托管、或买"专属实例"(dedicated deployment)——混合路由是平台期常态,网关的存在让它可执行。别用"技术自主性"说服财务,把盈亏线算给他看。

第 七 讲

多租户与 FinOps:把 AI 花销管成水电

AI 预算的崩盘姿势通常不是模型贵,是失控:一个批处理任务跑飞、一个 agent 循环空转、某团队拿旗舰模型做翻译。FinOps 三循环:可见(trace 级计量→按团队/应用/用户维度账单,周清);优化(闲置配额回收、缓存命中率、级联比例、模型替换的月度复盘);治理(预算三级防线:租户配额→软阈值告警+自动降级→硬停,策略提前定好,"停"不是惩罚是保险丝)。配套机制:内部计价(让业务方为 token 付费预算,免费的东西一定被滥用)、预算标签随请求头全链传播(归因到需求方而不是"平台背锅")。FinOps 做得好的信号:业务方主动来问"怎么把我的推理成本降一半"——成本变成了他们的 KPI 而不是你的。

图 6预算仪表盘 · 触发一次"某任务跑飞"

三级防线剧本:80% 告警 → 90% 自动降级(旗舰→中档,批任务直接排队) → 100% 硬停并挂值班工单。关键设计:降级策略由预算所有者预先声明(写进配额单),网关只执行,不临场决策——事故时刻没有冷静讨论,只有预案。

第 八 讲

模型生命周期:把换模型管成发布

"底层模型升级"在没人管时是灾难(效果悄悄漂移、老 prompt 失配、价格悄悄变),平台化后是流水线:注册表登记每个模型版本(能力卡:上下文长度/价格/延迟/评测集分数/已知风险)→ 候选升级先过离线评测矩阵(全任务线跑分对比)→ 5% 灰度(按租户/应用维度的分流,指标双跑对比)→ 达标推进、不达标一键回滚(prompt 与流量都跟着版本走,回滚无状态)→ 退役旧版本给迁移期限并强制下线。供应商 API 也有生命周期:"latest" 别名是定时炸弹,生产永远钉版本号日期;供应商弃用公告要有自动盯梢。把这套流程叫一个朴素的名字:模型变更管理——审计与合规部门最爱听的那一种。

第 九 讲

数据飞轮,以及它的红线

平台独有的复利:反馈闭环——显式(用户点赞点踩/改稿对照)、隐式(采纳/放弃/重生成)、裁判抽样(生产样本离线打分)三路汇入;脱敏后进偏好数据集,喂对齐与路由策略("哪类任务哪个模型赢"的先验表也是它产的)。飞轮的燃料管理比转动更重要,三条红线:① 用途授权(用户数据进训练池要有明示选择权,企业客户的协议里这是硬条款);② 留存分级(trace 全量≠全量存原文,PII 进掩码管线、按敏感度设 TTL);③ 数据集血缘(哪版模型用了哪批数据、批次里有没有被污染的爬取样本——出事要能追溯回滚)。飞轮不加速不转,但转错方向的飞轮比不转更糟:脏数据微调出来的模型,退化的方式是"自信地错"。

第 十 讲(终)

平台是产品:业务方是用户

AI 平台团队的交付物不是"接口",是产品的默认路径:接入 SDK 十分钟跑通、golden path 一路绿灯(标准路由+评测+观测自带)、偏离默认自己担责——治理靠"顺路"而非审批墙。度量自己的三北极星:业务方接入时长、平台承载调用的质量指标(不是"网关可用性 99.9%"的自嗨,是全链评测通过率)、单位价值成本下降曲线(FinOps 成果的月度呈现)。组织协作三件套写进平台章程:模型选型评审(平台+算法+业务三方)、事故复盘数据共享(每 case 进评测集)、成本透明(账单周报)。最后收拢这个系列的终局视角:Agent 应用层(第 6 册)决定业务上限,平台工程层(本册)决定这个上限能不能可持续地、可审计地、不破产地跑下去——架构师的座位,永远在"能跑"之后那一格。

要点面试/述职的终章答题框架:讲一次"效果回退事故"——如何 15 分钟内定位到 prompt 版本+模型别名漂移,靠 trace 回放钉死现场,靠 A/B 基线证明影响,靠注册表权限收紧防复发。把"平台能力"讲成"事故免疫能力",架构师的分就到手了。
